# nueve2siete 3d studio

The nueve2siete website, its admin panel and the custom product creators.

- **Phase 1:** site + admin + microphone prototype (size, shape, colors, sample text).
- **Phase 2 (in progress):** creators under `/disena-el-tuyo` ("design your own"), where the customer picks a
  product:
  - **Microphone with a logo** (`/disena-el-tuyo/microfono`): upload the logo, check whether it can be printed
    (Python engine) and preview it in 3D, raised or flat.
  - **Name keychain** (`/disena-el-tuyo/llavero`): type a name, add up to 2 printable emojis, pick font, size
    (S/M/L) and colors, and see it in 3D live. Product page at `/llaveros`.
  - Saving designs and orders is still missing (step 4).

## Structure

Three questions place everything: does it run on its own, is it shared code, or does it only exist on your
machine?

```
apps/        everything that runs and gets deployed
  web/         public website (Next.js), port 3000
  admin/       admin panel + API (Next.js + Payload), port 3001
  engine/      logo engine (Python + FastAPI), port 8000
libs/        shared code the apps import; never runs on its own
  configurator/  core rules: filaments, colors, nozzles, the microphone definition
  products/      product modules (rules and validation per product; the keychain for now)
  text-shapes/   text + emojis → printable 2D shapes (base, raised letters, key ring), fonts and emoji outlines
  cms/           Payload setup: collections, globals, config and generated types
dev/         local development only; never deployed
  db/            Postgres without Docker or sudo
```

### apps/web

```
src/app/                   pages (folders in English, URLs in Spanish; see "Routes")
src/app/media/             serves the files uploaded in the admin
src/assets/                the site's own images (imported from code; see "Images")
src/components/            UI: layout, home, mic (2D), creator, mic3d (3D viewer)
src/components/ui/         shared pieces: Popover, ColorSelect, FontSelect, EmojiPicker, SegmentedControl…
src/products/keychain/     keychain creator: text input, 3D viewer, 2D fallback, order message
src/lib/routes.ts          every page: Spanish URL ↔ English folder
src/lib/engine/            engine client: response contract, options and Spanish copy
```

### apps/admin

Payload's panel, where the content of the site is managed without touching code: products (sizes, box, logo
area, nozzle), filaments, leads from the contact form, projects, FAQs, files, users and site settings.

`src/app/(payload)/` is generated by Payload: don't edit it (the parentheses keep it out of the URL). The seed
lives in `src/seed/`.

### libs/cms

The Payload config is shared: the admin uses it for the panel, and the site reads and writes data with the Local
API (straight to Postgres, no HTTP). Only the admin changes the schema: in development it syncs the tables and
regenerates `payload-types.ts` when it starts.

## Stack

| Piece | Technology |
|---|---|
| Site | Next.js 16 (App Router) |
| Admin | Payload 3 on Next.js 16 |
| 3D viewer | three.js + React Three Fiber + drei (creator only, loaded separately) |

| Database | Postgres 17 |

| Monorepo | pnpm workspaces + Turborepo |

## First run

Requirements: Node 22+, pnpm (`npm install -g pnpm`) and [uv](https://docs.astral.sh/uv/) for the logo engine
(`curl -LsSf https://astral.sh/uv/install.sh | sh`).

```bash
pnpm install
cp apps/web/.env.example apps/web/.env       # change PAYLOAD_SECRET (openssl rand -base64 24)
cp apps/admin/.env.example apps/admin/.env   # same DATABASE_URL and PAYLOAD_SECRET as the web
(cd apps/engine && uv sync)                  # the engine's Python environment
pnpm dev                                     # local Postgres + site + admin + logo engine
pnpm seed                                    # in another terminal: filaments, product and FAQs
```

- Site: http://localhost:3000
- Admin: http://localhost:3001/admin (the first time it asks you to create the admin user)

## Routes

Page folders are in English; the URLs visitors see are in Spanish. `apps/web/src/lib/routes.ts` maps each page
(`/microfonos` → `microphones/`), and `next.config.ts` turns that map into rewrites (the Spanish URL renders the
English folder) and redirects (`/microphones` → `/microfonos`, so each page has a single address). Links, menus and
the sitemap read the same map: to change a URL, change it there.

## Images

- **The site's own images** (brand, photos, textures, illustrations) go in `apps/web/src/assets/` and are imported
  from code (`import logo from '@/assets/brand/nueve2siete-logo.png'`). Next.js optimizes them, gives them a
  content hash for caching, and the build fails if one is missing.
- **Files uploaded in the admin** (project photos) are saved in `.data/media` (set `MEDIA_DIR` on the server, the
  same folder for both apps). The site serves them at `/media/<file>`, only if they're registered in the admin.
- `app/icon.png`, `app/apple-icon.png` and `app/opengraph-image.tsx` stay in `src/app`: Next.js looks for them
  there.

## Notes

- **Local database:** lives in `.data/postgres`. To start from scratch: stop `pnpm dev` and delete that folder.
  If you prefer Docker, `docker compose up -d` starts the same database.
- **Schema:** in development the admin syncs the tables on its own. Before production we'll generate migrations
  (`pnpm --filter @nueve2siete/admin payload migrate:create`).
- **Content editable from the admin:** size measurements, available filaments, FAQs, project photos, WhatsApp
  number and legal info. While there is no WhatsApp number, the buttons go to the contact form.
- **Contact form:** saves each message in *Leads* (*Solicitudes* in the admin). The admin's public API can neither
  read nor create them; the site writes them through the Local API.
- **Seed with tsx:** `pnpm seed` uses `tsx` instead of `payload run`, because in Payload 3.90 `payload run`
  sometimes exits before the script finishes.
- **Creator and engine:** the browser uploads the logo to a Server Action (`design-your-own/actions.ts`, up to
  10 MB), which calls the engine at `ENGINE_URL` with the sizes, filaments and nozzle from the admin. The engine is
  not exposed to the internet and the image is not stored.
- **Keychain:** everything runs in the browser, no server round trip:
  1. The text is split into letters and emojis.
  2. The font's outlines become polygons (opentype.js).
  3. Clipper2 joins them, grows them into the base, adds the key ring and cuts its hole.
  4. three.js extrudes the result.

  The rules (sizes, limits, the thin-stroke check with the nozzle's minimums) live in `libs/products`. Sizes and
  limits can be edited in the admin (product of type "Llavero").
- **Emojis:** only the ones in the picker, which were checked to print at the smallest size. The picker draws
  them the way they're printed (one color, raised); typed or pasted emojis that aren't in the list are removed.
  See `libs/text-shapes/README.md`.
- `AGENTS.md` and `CLAUDE.md` in each Next.js app are generated by `next dev` (Next.js rules for coding
  assistants).
